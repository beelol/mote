# P2-05: OpenCode compatibility adapter

Status: in progress.

Environment: local macOS workspace, Rust 2021. Date: 2026-10-18.

The first compatibility slice moves OpenCode process construction behind `ServerFactory` while
leaving the v0 daemon path on the same process implementation. `OpenCodeAdapter` consumes the
common `mote-hrns` request and produces versioned model steps plus an opaque adapter checkpoint.
It rejects malformed events, failed completion, unknown checkpoint versions and checkpoints
owned by another task.

The adapter creates a fresh OpenCode session for every durable model step. Its restart fixture
uses a fresh fake server and session, then reconstructs the next prompt from the Mote checkpoint.
This proves the fixture does not depend on process-local OpenCode conversation state. The
production step API stops and aborts at the first tool proposal. It is not yet routed from the
daemon and must only be used with OpenCode configured to require permission for every exposed
Mote MCP tool.

The adapter cases cover tool proposal, fresh-server reconstruction, first-turn prompting, opaque
checkpoint versioning, task binding, timeout classification, non-object arguments, failed or
unfinished output and refusal of a stream that contains an already executed tool result.

At the end of the adapter-only slice, the guarded daemon configuration, internal compatibility
flag, daemon restart fixture and no-duplicate-action proof were still required.

## Daemon compatibility follow-up

The daemon now has an internal `MOTE_HRNS_OPENCODE_COMPAT=1` path. It is false for an absent value
and for every value except `1`, so the shipped default remains the existing v0 path. When enabled,
the think lane uses `OpenCodeAdapter` and preserves the existing normalized think-event and ledger
boundary for completed turns. A proposed tool is held and the turn fails closed rather than
allowing OpenCode to execute it.

The compatibility-only OpenCode configuration retains the v0 local Ollama model, keeps every
built-in tool disabled, exposes only the `moted` MCP server and applies permissions `* = deny` and
`moted_* = ask`. The normal v0 configuration is byte-for-byte generated by the original function
and gains no permission field.
