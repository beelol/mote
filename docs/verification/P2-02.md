# P2-02: runtime contracts

Status: complete.

Environment: local macOS workspace, Rust 2021. Date: 2026-10-18.

Added `crates/mote-hrns` with task, action, checkpoint, scoped identity, model-step and harness
types. The crate depends only on serde and serde_json. It does not run models or tools.

`cargo test -p mote-hrns --test contracts` first failed because the package did not exist.
After implementation it passed: 4 passed, 0 failed.

`cargo test --workspace` passed with exit 0. Explicit live tests remained ignored.
`cargo clippy --workspace -- -D warnings` passed with exit 0.
`cargo fmt -p mote-hrns -- --check` and `git diff --check` passed.

The tests cover nonempty identities through constructors and deserialization, every task and
action state, model-step round trips, rejection of unknown or missing step fields and non-object
tool arguments, and both harness selections using the same request contract. Checkpoints reject
adapter session fields.

This proves the initial data boundary only. It does not prove transitions, persistence, approval
enforcement, harness integration or restart recovery. The root criterion remains unchecked.

## Transition follow-up

On 2026-10-18, added guarded task and action transitions. The new transition suite first failed
to compile because `transition` did not exist. `cargo test -p mote-hrns` then passed all eight
tests. Fixtures exercise both harness selections, stale updates, terminal states, approval
ordering and refusal to restart committed actions. These are state guards, not proof that the
daemon enforces approvals.

The driver follow-up added adapter-driven transition fixtures for both harness kinds. The same
task, checkpoint and model-step contracts drive scripted OpenCode and Mote adapters. Checkpoints
have one product-neutral opaque JSON slot rather than typed fields for any adapter. Contract tests
reject adapter-specific fields at the checkpoint boundary. `cargo test -p mote-hrns` passed 24
tests: 4 contracts, 6 driver, 10 store and 4 transition tests. This completes P2-02.

The complete workspace test and `cargo clippy --workspace -- -D warnings` both passed after the
driver follow-up. Explicit live hardware and browser tests remained ignored.
