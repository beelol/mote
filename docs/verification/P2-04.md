# P2-04: Safe harness selection

Status: partial. Do not check P2-04 yet.

Date: 2026-10-18.

Environment: macOS Darwin 25.6.0 arm64, Rust 2021 workspace.

This increment adds the optional `agent.harness` configuration key without changing the exact v0
default configuration. An absent value resolves to OpenCode. Explicit values are limited to
`opencode` and `mote`, and reverting the first explicit setting removes the optional key instead
of writing a fabricated default value.

The harness selection state records configured, active and pending values. A selection applies
immediately only at a checkpoint. Requests made during a model step, tool execution, approval
wait, approval commit or store transaction remain pending. Reverting a pending request keeps the
current harness. Availability is checked at startup, at request time and again when the checkpoint
is reached. An unavailable harness returns a visible error and never silently falls back.

The production daemon now owns that selection state. Startup resolves the optional setting and
refuses an unavailable configured harness. IPC and Matrix changes validate availability before
persisting configuration, while revert updates both configuration and runtime state. Status and
pipeline snapshots expose configured, active and pending values. The Matrix host contract exposes
the harness selector plus active and pending readouts. A turn conservatively holds the runtime in
the model-step phase and releases it at a checkpoint on every return path.
