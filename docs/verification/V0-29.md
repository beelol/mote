# V0-29 verification

Item: A live think turn with `qwen3-coder:30b-64k` reads a file through `file_read` and answers,
with first token p50 under 3 s.

Section: docs/rfcs/v0.md#8-think-lane-local

## Status: OPEN (capability shown interactively; automated OpenCode runs deadlock — needs owner's environment)

Update: using the exact tools-disable config that made the manual run succeed did NOT help the
programmatic test — all 3 runs still time out at 120 s. So the deadlock is specific to OpenCode's
programmatically-spawned `run` in this context, not the config. The capability is proven by the
interactive manual run below; a reliable automated measurement needs the owner to run OpenCode in
their interactive environment (where it worked) or to resolve OpenCode's MCP-startup reliability.

## Environment
- Date: 2026-10-09
- Host: owner's Mac, Darwin 25.6.0 (arm64), 128 GB RAM
- Toolchain: cargo 1.89.0, Ollama 0.35.0, OpenCode 1.15.13

## Bugs found and fixed (driver work this round)
1. `moted mcp` crashed opening the context store when the data directory did not yet exist, so a
   freshly spawned MCP server (as OpenCode launches it) exposed no tools. Fixed by ensuring the
   data directory in `run_mcp`.
2. The MCP `initialize` response hardcoded `protocolVersion`; it now echoes the client's
   requested version. OpenCode's MCP handshake then completes.
3. `mote_harness::run_opencode` now takes a timeout and kills OpenCode if its MCP startup
   deadlocks (it otherwise hangs indefinitely — one run hung ~2 h before being killed).

## The capability works (one warm run)
With OpenCode's native file tools disabled so only the MCP tools exist, a live run produced:
```
step_start
TOOL: moted_file_read completed  out= The secret passphrase is blue-otter-42.
FINISH tool-calls
step_start
TEXT: The secret passphrase is blue-otter-42.
```
The model called the MCP tool `moted_file_read`, read notes.txt, and answered with its content.
So "reads a file through file_read and answers" is demonstrated live.

## Why the item is left open
The first-token p50 < 3 s gate is not met reliably:
- The bounded test (`live_think_reads_file_via_file_read`, 120 s per run) had 3/3 runs time out
  (`LIVE think first-token p50 = NaN over 0 completed run(s), 3 timeout(s)`). OpenCode's MCP
  startup intermittently deadlocks and the 30b tool loop can exceed 120 s.
- With MCP-only tools the model emits no preamble, so the first token is the post-tool-loop
  answer; on a 30b model that is seconds, above the 3 s budget.

This is a measured/observed miss, recorded here and left open per the contract (a missed number
is recorded, not forced). Closing it needs the owner to make the OpenCode + Ollama + MCP path
reliable and fast enough (persistently warm think model, OpenCode MCP-startup stability, and a
latency path that yields first token under 3 s). The think-lane parser (V0-27) and the MCP tool
server (V0-28) are verified independently.
