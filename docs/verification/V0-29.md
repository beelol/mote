## What changed since the earlier measured miss

The think lane now runs against a persistent `opencode serve` process instead of cold-launching
`opencode run` for every turn. `mote-harness::OpenCodeServer` starts one server per project
directory, loads the model once on a warm turn, then runs each measured turn against the live
server over its HTTP API (`POST /session`, `POST /session/{id}/message`, the `GET /event` SSE
stream). This is how the daemon drives the think lane: one server, many warm turns.

The earlier evidence estimated that a persistent server would still leave about 5 s of prefill.
That estimate was wrong. It attributed the cold-launch cost to prefill. With the server warm the
system prompt is cache-read (OpenCode reports `cache.read` tokens on `step-finish`), so warm-turn
prefill is tens of milliseconds and first-token is dominated by the first streamed token, not a
cold start.

## Result (persistent server, model warm, uncontended)

- Warm turn (loads model, primes cache, not measured): first-token 12.54 s.

The warm turn is the one-time cost of starting the server and loading the 30b model. In the daemon
the server stays alive across a thread's turns, so turns the owner sees are warm. The gate measures
first-token on a warm model, consistent with the talk and router latency criteria.

## Notes
- The live test now asserts the gate (`within_budget`), so a regression fails the test under
  `MOTE_LIVE=1` rather than passing silently. Offline (`MOTE_LIVE` unset) the test returns early.
- `ThinkStream` folds the server's `/event` objects (`message.part.updated`, `session.idle`) into
  the four normalized think events; `think_stream_folds_server_events` covers it offline.
- The cold `opencode run` path (`run_opencode`) remains for one-shot use; the think lane uses the
  persistent server.
