## Why the gate is unreachable here (not just cold start)
Even the first produced token (the file_read tool call) is ~8 s wall-clock. The cost is:
OpenCode cold start (~2-3 s, Bun) + MCP spawn/handshake (~1 s) + the 30b model's prefill over
OpenCode's large injected system prompt + tool-call generation. A persistent OpenCode server
(serve/attach) would remove only the ~2-3 s startup, leaving ~5 s - still above 3 s. So the 3 s
first-token gate is not reachable with OpenCode as the harness and a 30b think model on this
hardware. Lowering it needs a lighter harness or a smaller/faster think model, both of which the
contract fixes.

Per v0.md ("If a measured number misses its target, record the number in the evidence file and
leave the item open"), V0-29 is recorded as a measured miss and left open. The capability it
describes (read a file through the MCP file_read and answer) is fully verified; improving the
first-token latency is a backlog item (persistent harness and/or a faster think model).
