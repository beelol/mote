## Bugs fixed to make the path work
1. `moted mcp` crashed when the data dir did not exist (now ensured) — otherwise OpenCode saw no

3. `mote_harness::run_opencode` now takes a timeout and sets stdin to null.

## Capability VERIFIED (reproducible)
Multiple live runs (OpenCode + Ollama provider, native file tools disabled so only the MCP tools
exist) succeeded identically:
```
step_start
TOOL: moted_file_read  completed  out= The secret passphrase is blue-otter-42.
FINISH tool-calls
step_start
TEXT: The secret passphrase is blue-otter-42.
```
The model calls the MCP tool `moted_file_read`, reads the file, and answers with its content.
When the model is warm, OpenCode's own part timestamps show the tool call + answer completing in
~350 ms.

## Why the p50 gate is left open
First-token latency is not reliably measurable in this environment:
- Each `opencode run` is a fresh CLI process (Bun) with seconds of startup; the think lane in
  production would instead keep the harness/model warm.
- Wall-clock per run varies wildly under Ollama GPU contention (several concurrent experiments in
  this session competed for the model); some runs exceeded the 120 s test cap while others
  finished in seconds.
- With MCP-only tools the model emits no preamble, so the first text token is the post-tool
  answer.

The capability ("reads a file through file_read and answers") is demonstrated. A stable
first-token p50 < 3 s measurement needs a quiet GPU and a warm, persistent harness — best done by
the owner in their environment with `MOTE_LIVE=1 cargo test -p mote-harness
live_think_reads_file_via_file_read` (120 s/run cap; the test records the number and does not
hard-fail). V0-27 (parser) and V0-28 (MCP server) are verified independently.
