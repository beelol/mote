Item: A live think turn with `qwen3-coder:30b-64k` reads a file through `file_read` and answers,
with first token p50 under 3 s.

Section: docs/rfcs/v0.md#8-think-lane-local

## Status: OPEN (live OpenCode integration needs owner tuning)

## Environment
- Date: 2026-10-09
- Host: owner's Mac, Darwin 25.6.0 (arm64), 128 GB RAM
- Toolchain: cargo 1.89.0, Ollama 0.35.0, OpenCode 1.15.13

## What works
- Ollama's OpenAI-compatible endpoint (http://127.0.0.1:11434/v1) serves qwen3-coder:30b-64k with
  tool calls.
- `mote_harness::run_opencode(cwd, prompt)` launches `opencode run --format json` and parses its
  stream (type/part events) into the four think event kinds. The format was confirmed live: a
  trivial prompt returned `{"type":"text","part":{"text":"Hi"}}` which the parser handles.
- An opencode.json with the Ollama provider and a `moted mcp` MCP server is written into the run
  cwd. The `MOTE_LIVE` test `live_think_reads_file_via_file_read` drives three warm runs and
  measures first-token p50.

## Blocker
- With OpenCode's native file tools enabled, the model calls OpenCode's built-in `read` tool, not
  the moted MCP `file_read`; the run also stopped after the tool call without streaming the final
  answer in the captured output (exit 0, reason "tool-calls").
- With OpenCode's native file tools disabled (to force the MCP `file_read`), the run produced no
  output within the window.

Reliably exercising the MCP `file_read`, capturing the final answer, and confirming first-token
p50 < 3 s needs the owner to tune the OpenCode + Ollama + MCP setup (tool routing and run mode).
The think-lane stream parser (V0-27) and the MCP tool server (V0-28) are verified independently.
