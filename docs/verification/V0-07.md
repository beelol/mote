# V0-07 verification

Item: A subscriber more than 1,000 events behind receives `resync` and recovers from the log
without loss.

Section: docs/rfcs/v0.md#2-event-log

## Environment
- Date: 2026-10-08
- Host: owner's Mac, Darwin 25.6.0 (arm64)
- Toolchain: cargo 1.89.0
- Network: none

## Notes
Each subscriber has a bounded queue. When a broadcast pushes it past LAG_LIMIT (1,000), the
backlog collapses into a single `resync` event. Test `stalled_subscriber_gets_resync` never
drains, appends 1,050 events, observes the `resync`, then a fresh subscription from cursor 0
replays every retained event, proving recovery without loss.
