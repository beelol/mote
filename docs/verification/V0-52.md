## Notes
`request_file_write` executes immediately inside the data directory and, outside it, stores a
`pending` approval (24 h expiry) and writes nothing. `approve` executes the stored write only
while pending and unexpired; `deny` and expiry leave it unexecuted. `approval_card` returns the
surface tree (a stack with the prompt and Approve/Deny actions) for the client to render.
`file.write` now commits that card as a validated `ui.surface` event on the requesting thread.
The card's `approve:<id>` and `deny:<id>` events return through `ui.event` and change only the
matching pending, unexpired approval in the same thread. Tests cover pending (no write), card
emission, cross-thread rejection, replay rejection, deny (no write), approve (write), expiry (no
write), unknown ids and the immediate inside-dir write.

The screenshot of the rendered card requires the mote-client GUI (V0-43+), which needs the
owner's desktop session. This item is left open until that screenshot exists.
