## Headless client behavior

Updated 2026-10-10 by `fix(client): apply pipeline config asynchronously`.

The production Config tab now records typed dirty keys and sends one fixed-order batch to a
background worker. Boolean and integer text is parsed before queueing. Invalid values never enter
the IPC batch. An edit returned to its snapshot value is no longer dirty. Apply is disabled while a
batch or snapshot is pending.

The worker completes every `config.set` call before returning one batch result. Failed keys remain
dirty and show the daemon error. A successful key clears only when its submitted edit revision is
still current. Any successful request starts one snapshot refresh after the full batch. Snapshot
installation updates clean keys and preserves failed or concurrently edited keys. A successful
snapshot does not clear a configuration error.

In-flight submitted revisions and values are separate from dirty edit state. The regression starts
at O, submits A, edits back to O while A is pending, accepts A and installs an A snapshot. O remains
visible and dirty, then queues as the next typed request.

The complementary regression starts at O, submits A, edits to B and returns to A while the request
is pending. The successful response advances the baseline to A, recomputes the visible A as clean
and queues no follow-up request. The O to A to O case remains dirty.
