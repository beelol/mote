# V0-11 verification

Item: `events.subscribe` streams from a cursor over the socket, and the client crate reconnects
and resubscribes from its cursor after a dropped connection.

Section: docs/rfcs/v0.md#3-ipc

## Environment
- Date: 2026-10-08
- Host: owner's Mac, Darwin 25.6.0 (arm64)
- Toolchain: cargo 1.89.0
- Network: none

## Notes
`EventStream` sends `events.subscribe {scope_id, cursor}`, reads `{"event":{...}}` lines, and
tracks the last delivered seq as its cursor. On EOF or a hard read error it reconnects and
resubscribes from that cursor, so the server only resends `seq > cursor` and nothing arrives
twice. Test `subscribe_streams_and_reconnects_without_duplicates` reads three events, forces a
disconnect mid-stream, appends five more, then collects the rest and asserts all ten arrive
strictly increasing (in order, no duplicate).
