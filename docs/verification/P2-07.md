# P2-07: Guarded action receipts

Status: in progress.

Environment: local macOS workspace, Rust 2021. Date: 2026-10-18.

This increment replaces the driver's in-memory receipt illusion with a durable receipt table.
Action requests have a canonical SHA-256 hash over their stable action ID, task ID, name and
recursively sorted arguments. A receipt commit validates that exact hash, inserts one receipt,
changes the action from running to committed and appends the redacted event in one SQLite
transaction.

`HrnsStore` now exposes revision-guarded claim, commit, deny and fail operations. Replaying an
identical committed receipt is inert. A different receipt, altered request hash, stale revision or
wrong prior state fails closed. A restarted driver never dispatches an action that another driver
already claimed. It records the action as failed with an indeterminate outcome instead of risking
a duplicate outward effect.

The existing browser and file-write approval records can now bind a distinct HRNS action ID and
request hash without replacing their exact intent hash. One HRNS action creates one approval per
host. Repeated identical creation returns the existing approval; changed content or hashes are
rejected. The file-write bridge remains fail closed after restart when its exact in-memory intent
is unavailable.

The daemon's approve and deny RPCs now reconcile a bound approval back into the durable action
state. Reconciliation resolves the action's stored account and realm rather than assuming the
personal realm, validates the canonical request hash and is inert when the same terminal approval
is observed again. An approved file effect is observed through its terminal approval record and is
not dispatched a second time.

P2-07 remains open until the daemon's durable task runtime creates these bound approvals from
harness proposals and uses the production action executor end to end. Arbitrary remote effects without downstream
idempotency cannot honestly guarantee completion exactly once. Mote must consume authority once
and expose an indeterminate result rather than redispatch them.
