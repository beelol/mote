# V0-53 verification

Item: `moted install` loads the launchd agent, the daemon survives logout and login, and `moted
uninstall` removes it.

Section: docs/rfcs/v0.md#16-service

## Status: OPEN (install, KeepAlive restart and uninstall verified live; unload failure recovery is unit tested; the logout/login survival still needs the owner's session)

## Environment
- Date: 2026-10-10
- Host: owner's Mac, Darwin 25.6.0 (arm64)
- Toolchain: cargo 1.89.0

## What is implemented
`moted install` writes `~/Library/LaunchAgents/com.mote.moted.plist` (KeepAlive, RunAtLoad,
StandardOut/ErrPath under the data directory, MOTE_HOME env) and runs `launchctl load -w`.
`moted uninstall` runs `launchctl unload -w <plist>` before removing the plist. A process launch
error or nonzero exit returns a meaningful error and preserves the plist as recovery state. Only a
successful unload removes the plist and prints `removed com.mote.moted`. A missing plist remains an
idempotent success when launchctl reports success.

## Live run (2026-10-10)
Run with `MOTE_HOME` pointed at a throwaway directory so the agent's data, socket and logs stayed
out of the real mote data directory; the fixed label `com.mote.moted` was not otherwise in use.

## What is verified and what remains
Verified live: install loads an active agent with KeepAlive and RunAtLoad, the program and env are
the ones written, the daemon comes up (socket), KeepAlive restarts it after `kill -9`, and
uninstall unloads and removes it with nothing left running.

Verified with an injected one-shot command runner: the uninstall path invokes exactly
`launchctl unload -w <plist>`. A nonzero exit with stderr returns that detail and preserves the
plist. A nonzero exit without stderr returns a nonempty fallback error and preserves the plist. A
launch error returns its detail and preserves the plist. A successful unload removes an existing
plist and also succeeds when the plist is already absent. No test invokes real launchctl.

Not yet verified: the literal "survives logout and login". A `kill -9` restart proves the agent
restarts the daemon on process death, but RunAtLoad across an actual session logout/login can only
be checked by the owner. To close V0-53 the owner runs `moted install`, logs out and back in, runs
`moted status` to confirm the daemon is running, then `moted uninstall`, and records the result
here.

## Persistent paired-host run (2026-10-17)

Environment: owner's Mac, Darwin 25.6.0 (arm64), physical iPad Pro 11-inch (M4) on iPadOS 26.5,
and the production Mote data directory. The foreground development daemon was stopped before the
service was loaded.

```text
$ ./target/debug/moted install
loaded com.mote.moted from /Users/bilal/Library/LaunchAgents/com.mote.moted.plist

$ launchctl print gui/$(id -u)/com.mote.moted
state = running
program = /Users/bilal/projects/mote/target/debug/moted
runs = 1
pid = 92856
properties = keepalive | runatload | inferred program

$ ./target/debug/moted status
socket:        /Users/bilal/Library/Application Support/mote/moted.sock
uptime:        5 s
loaded models: (none)
last event:    seq 9
```

The driver then sent `SIGTERM` only to `gui/501/com.mote.moted`. Launchd restarted the service in
one second. Its run count changed from 1 to 2 and its process ID changed from 92856 to 97330. The
last exit code was 0. A second status call connected to the same socket and retained event sequence
9. The LaunchAgent remains installed so the paired iPad can keep using the persistent host.

This strengthens the live install and KeepAlive evidence against the production Mote state. It
does not replace the literal logout and login clause, so V0-53 remains open.
