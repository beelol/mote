Item: `config.set` validates the value, writes a `config.changed` event with old and new,
applies it on the next turn, and `config.revert` restores it.

Section: docs/rfcs/v0.md#4-config

- Network: none

## Notes
`ConfigStore::set` checks the key against a schema and its type, applies the change to the
in-memory config and the file, and appends a `config.changed` event `{key, old, new}`. Lanes
read the config value per turn via `get`/`get_json`, so a change applies on the next turn.
`revert(seq)` reads the event and restores its `old` value, recording a second event. The
daemon exposes `config.get`, `config.set` and `config.revert` over IPC. Test
`set_records_change_and_revert_restores` changes `models.talk`, inspects the change event's old
and new, reverts, and confirms the restore and the second event. `unknown_key_and_wrong_type_are_rejected`
covers validation.
