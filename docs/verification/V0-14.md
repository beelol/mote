# V0-14 verification

Item: Setting a model whose file size exceeds the memory gate is refused with a reason that
names free memory and model size.

Section: docs/rfcs/v0.md#4-config

## Environment
- Date: 2026-10-08
- Host: owner's Mac, Darwin 25.6.0 (arm64)
- Toolchain: cargo 1.89.0
- Network: none (scripted Ollama server on loopback)

## Notes
`OllamaGate` asks the (scripted) Ollama for the model's size via GET /api/tags and runs
`memory_gate(available_memory_bytes(), size)`, which requires free >= 1.25x size and otherwise
returns a reason naming both the model size and free memory. `ConfigStore::set` runs the gate on
`models.*` keys and surfaces the reason as `SetError::Rejected`. Test
`oversized_model_is_refused_naming_memory_and_size` reports a 500 GB model (1.25x = 625 GB,
above any real free memory) and asserts the rejection names size and free memory.

$ cargo test -p moted oversized_model_is_refused_naming_memory_and_size
