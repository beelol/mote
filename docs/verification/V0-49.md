## Notes
The production talk, router and think paths record each outbound call as a `model.request` event
on the `pipeline` scope immediately before invocation. They record one `model.response` event
after invocation. A stable `request_id` correlates the stored redacted request with total latency,
first-token latency when available and status. Each call also writes one pack and one ledger row.
The client's Requests tab reads every retained request row and joins timing only by `request_id`.

Test `requests_store_redacted_payloads_no_secrets` plants `sk-...` in a production talk turn and
asserts the stored request contains no secret, carries the `[redacted]` marker and has one
correlated response with measured timing. Test `full_turn_records_talk_and_router_calls_once`
drives the production talk and router path and asserts one request, response, pack and ledger row
per model call. The two think boundary tests assert the same correlation and accounting on success
and failure, including the harness-provided first-token duration.
