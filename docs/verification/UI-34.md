# UI-34: committed display remains stable

Date: 2026-10-10.
Environment: macOS 26.6.2 (25G83), arm64, Rust 1.89.0, Cargo 1.89.0, egui 0.31.0.
Status: verified against the current backlog Verify clause.

Passive test hooks record each node actually visited by `surface::draw`.
Each observation contains its egui namespace, structural child path, typed node and painted bounds.
Bounds come from the real paint shapes, with rectangle geometry independent of focus stroke width.
The hooks do not wrap widgets, allocate controls or change renderer layout.
The reusable harness renders the real application chat view at 800 by 600 logical points.

Each of the ten unchanged fixtures is framed and split at every byte before completion.
The 1,963 incomplete cases compare the entire observation vector with the previous committed frame.
They repeat that comparison while tapping and pressing Enter at candidate positions and on the prior
committed action.
The typed committed tree, identities and rectangles remain exactly equal.
Malformed complete payloads and malformed frame finalizations preserve the same observations.

Completing the valid frame changes the committed surface exactly once.
The rendered observation vector equals a separately rendered complete fixture.
Repeated idle frames do not cause another replacement.
The Matrix regression adds 173 action/form prefixes, 297 rejected finalizations and 48 valid finishes.
Each valid finish produces one whole-surface switch.
The unsupported form remains wholly absent.

A mutation that cleared the display before validation failed with an empty observation vector.
A mutation that committed a complete Matrix candidate before `finish` failed the event sequence check.
Both temporary mutations were removed before final verification.
