# V0-05 verification

Item: Subscribing with a cursor replays every event after it in order and then streams live
events with no duplicate.

Section: docs/rfcs/v0.md#2-event-log

## Environment
- Date: 2026-10-08
- Host: owner's Mac, Darwin 25.6.0 (arm64)
- Toolchain: cargo 1.89.0
- Network: none

## Notes
`subscribe(scope, cursor)` reads the replay snapshot (`seq > cursor`) while holding the log
lock, so no live event can land below the snapshot. Replay drains before live events.
Test `two_subscribers_at_different_cursors` registers subscribers at cursor 0 and cursor 5
(replay counts 10 and 5), then one live append reaches both exactly once, with no duplicate.
