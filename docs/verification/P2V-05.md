# P2V-05 owner-activated voice supervision

Status: complete.

Date: 2026-10-20

Environment: Apple Silicon macOS, Rust 1.89 workspace on `main`. No microphone capture was
started during deterministic verification. This Mac does not currently contain the configured
local Whisper model, so the production preflight was verified to report Unavailable without
spawning a listener or exposing a local path.

## Verified behavior

Normal `moted` builds contain an Off-by-default voice supervisor and sibling
`mote-voice-listener` binary. Voice starts only through the explicit owner `voice.start` RPC.
Optional `voice.input` and `voice.model_path` settings are accepted without changing the v0
default TOML; fixture input and remote model URLs are refused.

The supervisor checks platform support, the local listener and local model before spawning. A
microphone listener emits Ready only after the macOS capture API starts successfully, so a denied
platform permission cannot appear as Listening. State and error events are redacted. Concurrent
starts spawn once; Stop wins over an in-flight spawn; malformed output and crashes use progressive
bounded backoff and become Unavailable after three rapid failures.

Voice status is included in the daemon pipeline snapshot. A driver-level daemon test proves that
an unavailable voice start does not prevent the same daemon from completing a typed turn.

## Limits

P2V-05 proves local daemon supervision and typed fallback. The current Mac needs a separately
provisioned local Whisper model before real transcription can run. Final utterance routing,
ledgered STT and TTS, speech interruption, paired iPad Start and Stop, daemon-bound avatar state
and complete Simulator journeys remain P2V-06 through P2V-08.
