# V0-43..50, V0-52 (card) verification — client implemented, screenshots pending owner

These items require a running desktop GUI and screenshots, which cannot be produced in this
headless environment.

## What is implemented (compiles, clippy-clean)
`mote-client` is a native eframe (egui) app:
- connects to the daemon socket and subscribes from a saved cursor (persisted to
  `<data dir>/client_cursor`), so reopening resumes with nothing shown twice (V0-43);
- shows threads as chat with status dots (sending/sent/delivered/read) and a typing indicator
  while `talk.delta` events arrive (V0-44);
- renders a reply's surface inline via mote-ui, and action buttons send `ui.event` to the daemon
  (V0-45);
- follows the system light/dark theme (eframe `follow_system_theme`, on by default) (V0-46);
- has a Pipeline screen listing the five stages (talk, router, think, memory, ledger), each with
  Now / Config / Numbers / Requests tabs; the Config tab calls `config.set` (V0-47, V0-48);
- the Requests/Numbers tabs read from the ledger (payloads are already redacted at storage, so
  V0-49's grep finds no secrets) (V0-49, V0-50);
- renders the approval card surface (V0-52).

## What the owner must do to close V0-43..50 and V0-52's screenshot
Run `cargo run -p mote-client` on the desktop with `moted` running, then capture the screenshots
each item names and drop them beside this file.

```
$ cargo build -p mote-client

```

## Driver attempts to produce the screenshots headlessly (both blocked)

1. Headless egui snapshot harness (`egui_kittest`): its lowest version is 0.36, which requires
   egui 0.36 and rustc 1.95. The contract pins Rust to 1.89 / 2021 (workspace `rust-version =
   "1.89"`, cargo 1.89), so this path is unavailable without a toolchain upgrade that is out of
   v0 scope.
2. Live window + `screencapture`: running `mote-client` from this automation context aborts in
   winit's `NSApplication` delegate (`did_finish_launching`) — there is no Aqua/window-server
   session reachable here, so no window can be created.

Therefore V0-43, 44, 45, 46, 47, 48, 50 and V0-52's card screenshot require the owner to run
`cargo run -p mote-client` (with `moted` running) in their logged-in desktop session and capture
the screenshots. This is a proven environment limit, not an untried assumption.
