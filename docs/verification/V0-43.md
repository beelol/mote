## Runtime implementation

`mote-client` remains a separate eframe consumer process.
The no-argument path connects to the daemon socket and subscribes from the saved cursor.
It reconnects after startup failure, disconnect or `resync` with backoff capped at one second.
The durable cursor advances only after the UI reducer applies an event.
Cursor replacement uses a unique same-directory file created with `create_new`.
The client writes and syncs that file, renames it over the committed cursor and syncs the parent
directory before accepting another queued event.
Missing cursor files start from zero without a warning.
Empty, malformed, negative, overflowing and unreadable cursor files start from zero with a generic
visible warning that does not include file contents.
If cursor persistence fails, the just-reduced event stays visible and retains its latency and
pipeline accounting.
The client then shows a dedicated cursor issue and does not reduce later queued events.
Unrelated worker success does not clear that issue.
Its event reducer validates incoming surfaces through `mote_ui::validate`.
Unknown types, unknown keys and malformed surface payloads are ignored fail-closed.
Ordinary talk text, typing and delivery behavior are covered by reducer tests.
An ordinary client turn emits one redacted `turn.user` event before lane events.
Optimistic user messages use stable local ids and reconcile with that event without duplication.
Failed sends remove only their pending message and restore its text for retry.
The focused renderer draws all eleven existing `mote_ui::Node` variants.
No schema, fixture, Matrix grammar, daemon or tree type was changed.
Action clicks preserve the existing `ui.event` event string.
Fields, toggles and selects retain local values for the current surface instance.
Their state is not a new wire protocol or a claim of keyed reconciliation.

Vector follows system light and dark selection.
Tests cover both exact palettes, monospace type, sharp corners, structural strokes and spacing.
Controls use a thirty-six point visual height and a forty-eight point touch region.
Tests cover a click in the padded region and red keyboard focus with Space activation.
Progress uses a thin red stroke and a readable percentage.
Keyed materialize animation is deferred because the v0 tree carries no keys.
The runtime does not simulate identity or delay task use with an initial reveal.
