# UI-22 partial verification

Date: 2026-10-10.

Environment: macOS 26.6.2 build 25G83 on the repository Mac. Rust is 1.89.0. egui is 0.31.0.
AccessKit is 0.17.1. `accesskit_consumer` is 0.26.0. The macOS adapter selected by eframe is
`accesskit_macos` 0.18.1.

The observation harness enables AccessKit on the real egui context and renders through
`MoteApp::draw_shell`. It builds an `accesskit_consumer::Tree` from the emitted update. Traversal
uses `accesskit_consumer::common_filter`, which is the same filter used by the macOS adapter.

The checked-in JSON goldens under `mote-client/golden/roles` omit ids, bounds and focus. They retain
the nested role, name, value, toggle and numeric progress contract. Exact equality detects missing,
misordered and duplicate semantic nodes.

Command:

```text
cargo test -p mote-client accessibility_ -- --nocapture
```

Output:

```text
running 1 test
22 exact production-shell AccessKit role-tree comparisons
test app::observation::accessibility_tests::accessibility_all_fixtures_and_gallery_match_exact_role_trees ... ok

test result: ok. 1 passed; 0 failed
```

The 22 comparisons cover all ten JSON fixtures and the gallery at 800 by 480 and 1280 by 800.
Text, list, list item, table, row, column header, cell, text input, switch, combo box, button,
progress indicator, log and chat list item semantics are present. Visual Field, Select and Progress
labels are hidden after their names are assigned to the semantic control. Scroll interaction nodes
and the other visual control nodes are also hidden, so the filtered tree contains one semantic node
per current-v0 node.

UI-22 remains open. An unlocked native Mac must dump the NSAccessibility tree through the eframe,
winit and AccessKit adapter. The other renderer still needs its role-tree comparison. Typed alt
text, live status semantics and overlay focus remain gated by consumer-contract additions and are
not claimed here.
