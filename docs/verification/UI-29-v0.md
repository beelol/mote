# UI-29 v0 committed surface event admission

Date: 2026-10-10.

Environment: macOS 26.6.2 (25G83), arm64, Rust 1.89.0, Cargo 1.89.0.
Tests use temporary data directories and local scripted services.
No live model calls, model pulls or native screenshots were used.

Status: verified for the current v0 Matrix controls. UI-29 remains partial.
The broader full-catalog activation and context clauses remain open.

The daemon retains a committed contract per thread.
The contract contains the lowered Node, its interactive structural paths, exposed field types,
enum members and exposed action argument contracts from the trusted host manifest.
It is installed only after the matching `ui.surface` append succeeds.
Its revision is that event's sequence number.
Admission and Matrix replacement share the retained-source lock.
A concurrent replacement cannot invalidate an admitted event before its effects finish.

The client retains the sequence from the displayed Matrix surface event.
The real renderer attaches zero-based child-index paths to controls.
The ordered event worker sends this request envelope:

```json
{"thread":"main","event":"refresh","args":{},"surface_seq":19,"node_path":[0,1]}
```

The path is empty for a root control.
The v0 Node schema and production `ui.surface` payload remain unchanged.
Stored activation payloads retain the existing `event` and `args` shape.
Every stored event still passes through EventLog redaction.
Activation args contain validated values and field identities, with no Matrix source text.

The regression covers 24 forged request cases against a committed dashboard.
It rejects unknown actions, absent fields, missing or extra arguments, wrong value types,
unapproved model values, malformed or missing paths, inert nodes, wrong events for nodes,
wrong fields for nodes, stale or missing revisions and an event from a rejected candidate.
It also rejects approval actions carrying Matrix context.
Each case asserts no appended event, no file or in-memory configuration change,
no source or committed-contract replacement, no approval effect, no scripted model request,
no context pack and no ledger row.

Separate tests require a visible Refresh control and exactly empty action args.
They preserve the prior source and contract after failed whole-source and candidate appends.
Successful candidate commits accept the boolean local-only field and three model enum fields.
Every successful change refreshes the surface and makes the preceding sequence stale.
The client test drives the reducer, a nested rendered button and the actual ordered worker's
parameter construction after two replacements.
It observes sequence 19 and path `[0,1]`.
Existing toggle, select and rollback tests pass.

Legacy approval cards have a separate route for `approve:<id>` and `deny:<id>`.
That route accepts empty args without Matrix context and keeps the current thread, pending-status
and expiry checks.
Unrecognized non-Matrix events have no fallback route.
No-op approval attempts are not stored as accepted activations.
