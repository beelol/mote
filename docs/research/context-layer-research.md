# Context layer research notes

Date: 2026-10-08. Companion to `docs/rfcs/context-layer.md`.

These are raw notes. Each entry names the source, the facts taken from it, and measured numbers where they exist. "Unknown" marks a fact the research did not find. Crate metadata (version, license, release date) comes from the crates.io API on 2026-10-08 unless an entry says otherwise. Local measurements were taken on the owner's Mac (Apple M5 Max, 128 GB, macOS Darwin 25.6.0, sqlite3 CLI 3.51.0) on 2026-10-08 with the sqlite3 and mdfind command line tools. No code was written. The research was split across six research agents and the author. Each agent fetched its own pages and reported URLs. Facts that only appeared in a search snippet are marked "search snippet".

## 1. Local measurements on the owner's Mac

### 1.1 SQLite multi-hop queries at 100k and 1M edges

- Method: two databases built with `sqlite3`, WAL mode, `synchronous=NORMAL`. Table `edge(src INTEGER, dst INTEGER)`, random edges over N/10 nodes (average out-degree 10), indexes on `src` and on `dst`, `ANALYZE` run. Timings from `.timer on`, warm cache, best of three.
- Numbers, 100,000 edges (file 3.3 MB):
  - 2-hop out-neighbourhood by two joins from one seed: 0.05 ms (132 distinct nodes).
  - 3-hop by three joins: 0.5 ms (1,258 nodes).
  - Recursive CTE bounded to depth 2: 0.1 ms. Depth 3: 1.6 ms.
  - Both-direction 2-hop written as a `UNION ALL` view over the edge table: 88 ms. The planner materializes the view, so this shape must not be used.
  - Both-direction 2-hop edge load written as four indexed lookups with `LIMIT 200`: 0.04 ms.
- Numbers, 1,000,000 edges (file 36 MB with both indexes):
  - 2-hop by joins: 0.04 ms (76 nodes). 3-hop by joins: 0.4 ms (780 nodes).
  - Recursive CTE depth 2: 0.09 ms. Depth 3: 0.9 ms.
  - Both-direction 2-hop as a `UNION ALL` view: 1,300 ms. Same planner trap.
  - Edge load with `LIMIT 200`: 0.07 ms.
  - Twenty 2-hop queries from twenty seeds, each in a fresh `sqlite3` process: 80 ms wall for all twenty, so under 4 ms each including process start.
- Numbers, hub node: 2,000 out-edges and 2,000 in-edges added to one node in the 1M graph. 2-hop out from the hub: 28 ms (18,234 nodes). 3-hop out: 310 to 344 ms (84,068 nodes). Unbounded both-direction 2-hop edge load from the hub: 18 ms (85,651 edges). The same load with `LIMIT 200`: 0.03 ms.
- Facts taken: with indexes on both edge columns, fixed-depth neighbourhood queries in SQLite are sub-millisecond at 1M edges for ordinary nodes. Hubs dominate the cost, so the walk must be bounded per hop. Query shape matters more than engine choice at this scale.
- Unknown: the same numbers on a Raspberry Pi 5 and on a graph with real-world degree distribution. The spike measures both.

### 1.2 Spotlight on the owner's Mac

- Method: `mdutil -s /` and timed `mdfind -onlyin ~/projects` queries.
- Numbers: indexing enabled on `/`. `kMDItemContentModificationDate >= $time.today(-7)` over `~/projects` returned 306,049 files in 8,051 ms. The one-day variant returned 54,790 files in 1,511 ms. A `kMDItemTextContent` phrase query over `~/projects` returned 26 files in 693 ms.
- Facts taken: Spotlight answers content queries in under a second but returns build artefacts and dependency trees unless the query excludes them. A file connector needs ignore rules before Spotlight results are useful.

### 1.3 TCC and local stores

- Method: existence and size checks with `du` and `ls`, and a 15-byte header read, from the same terminal process that ran this research. No store contents were read.
- Facts: `~/Library/Mail` listing fails with "Operation not permitted". `~/Library/Calendars` and `~/Library/Safari` listings fail the same way. A header read of `~/Library/Messages/chat.db`, `~/Library/Safari/History.db` and the Notes `NoteStore.sqlite` fails with "Operation not permitted". A header read of Chrome's `History` file succeeds and returns `SQLite format 3`. So macOS TCC blocks Mail, Messages, Safari, Notes and Calendar for a process without Full Disk Access, and Chrome's profile is readable without it.

### 2.1 SQLite with graph tables plus petgraph (the memory doc's recommendation)

- URL: https://sqlite.org/about.html, https://crates.io/api/v1/crates/sqlite-vec, https://alexgarcia.xyz/sqlite-vec/features/vec0.html, https://github.com/dpapathanasiou/simple-graph, https://docs.rs/crate/sqlitegraph/=3.0.5, https://duckdb.org/2026/08/25/how-duckdb-runs-recursive-ctes-faster, https://arxiv.org/abs/2609.01525
- Facts: SQLite says "With all features enabled, the library size can be less than 900KiB" and "A complete SQL database with multiple tables, indices, triggers, and views, is contained in a single disk file." sqlite-vec `max_stable_version` is 0.1.9 (2026-03-31). Pre-releases 0.1.10-alpha.2 to alpha.4 exist (latest 2026-05-18). License MIT or Apache-2.0. vec0 partition key columns shard the index by a key such as `user_id`, an `=` constraint on a partition key limits the KNN scan to that partition, at most 4 partition keys, each key value should hold hundreds of vectors. Metadata columns (TEXT, INTEGER, FLOAT, BOOLEAN, up to 16) allow `=`, `!=`, `>`, `>=`, `<`, `<=` in KNN filters. Auxiliary columns (`+` prefix, up to 16) store unindexed data and cannot be filtered. simple-graph (MIT) stores JSON nodes and an edges table and traverses with CTEs in Python, Go, Julia, R, Dart and Swift. sqlitegraph 3.0.5 (GPL-3.0-only, so not usable) published BFS timings for a SQLite backend: 2.5 ms at 1K nodes and 5K edges, 26 ms at 10K/50K, 160 ms at 50K/250K, and point lookups of 15 to 27 microseconds, on a Ryzen 7 7800X3D with tmpfs. DuckDB's 2026-08-25 post ran a recursive reachability CTE over 1,000,000 edges and 100,000 nodes in 4.051 s on v1.5.5 and 0.095 s on the v2.0 preview, and reported that a six-hop recursive query in another engine went from 1.8 s to 241 s when data grew tenfold because of a plan pathology. arXiv 2609.01525 (Gene Zhang, 2026-09-01) argues that a relational engine with a graph front end matches native graph engines on analytical queries.
- Numbers: see section 1.1 for the author's measurements. sqlite-vec scanned 100,000 float32 vectors of 384 dims in 67.84 ms on an M1 Pro (from `docs/research/memory-research.md` 3.7).
- Unknown: a published SQLite 2-hop number at 1M edges from a third party. The author's own measurement stands in.

### 2.7 Graph query engine evidence used for the comparison

- The Kuzu report's own thesis is that factorized, worst-case-optimal joins win on many-to-many joins at LDBC SF100 scale (hundreds of millions of edges). mote's graph is four to five orders of magnitude smaller. At 1M edges the author's SQLite joins take under 1 ms for ordinary nodes. The engines differ at a scale mote does not reach on one person's data.
- The SurrealDB numbers show that an LSM document-graph engine answers depth-2 traversals in about 2 to 3 ms on fast hardware. That is adequate for the think lane and too slow for a 40 ms talk lane budget that also needs vector and text lanes.

### 6.5 Reciprocal rank fusion and alternatives

- URL: https://api.semanticscholar.org/graph/v1/paper/DOI:10.1145/1571941.1572114, https://www.elastic.co/guide/en/elasticsearch/reference/current/rrf.html, https://docs.weaviate.io/weaviate/concepts/search/hybrid-search, https://docs.opensearch.org/latest/search-plugins/search-pipelines/normalization-processor/, https://docs.opensearch.org/latest/search-plugins/search-pipelines/score-ranker-processor/, https://qdrant.tech/documentation/concepts/hybrid-queries/, https://github.com/atlantis-nova/hybrid-dbsf, https://arxiv.org/abs/2210.11934, https://docs.lancedb.com/reranking/rrf.md
- Facts: RRF score is the sum over lists of 1 divided by (k plus rank). Elastic `rank_constant` default 60. Weaviate `alpha` default 0.75, `rankedFusion` uses 1 over (rank plus 60), and `relativeScoreFusion` (default since v1.24) min-max scales each list and sums with alpha weights. OpenSearch normalization `min_max` (default), `l2`, `z_score`, combination `arithmetic_mean` (default). Qdrant offers `rrf` and `dbsf`. DBSF normalizes each list with (s minus (mu minus 3 sigma)) over 6 sigma. Bruch, Gai and Ingber (2023): a convex combination of normalized scores beats RRF in and out of domain, and RRF is sensitive to its parameters. LanceDB: "Experiments indicate that k = 60 was near-optimal, but that the choice is not critical."
- Numbers: k 60 across Elastic, OpenSearch, Weaviate and LanceDB.

CloudEvents 1.0.2 required attributes: `id` (non-empty string, unique within the producer), `source` (non-empty URI-reference), `specversion` (`1.0`), `type` (non-empty string, reverse-DNS prefix recommended). ## 8. Identity, realms and token storage (report from the identity research agent)

### 8.1 Google identity

- URL: https://developers.google.com/identity/openid-connect/openid-connect, https://developers.google.com/identity/protocols/oauth2/web-server, https://developers.google.com/identity/protocols/oauth2/native-app
- Facts: `sub` is "unique among all Google Accounts and never reused" and is the only safe user key. "Don't use the `email` field as a unique identifier for a user" and you "can't rely on the domain of the `email` claim" to detect Workspace users. `hd` is present "only if the user belongs to a Google Cloud organization" and "The absence of this claim indicates that the account does not belong to a Google hosted domain." The `hd` ID token claim "can be trusted" because it is inside a signed token. userinfo endpoint `https://openidconnect.googleapis.com/v1/userinfo`. `login_hint` accepts an email or `sub`. `prompt=select_account` forces the chooser. Native apps cannot use incremental authorization. The token response `scope` field lists the scopes actually granted and apps "must verify which scopes were actually granted".
- Numbers: `sub` up to 255 ASCII characters.

### 8.2 Microsoft identity

- URL: https://learn.microsoft.com/en-us/entra/identity-platform/id-token-claims-reference, https://learn.microsoft.com/en-us/entra/identity-platform/optional-claims-reference, https://learn.microsoft.com/en-us/graph/api/user-get, https://learn.microsoft.com/en-us/graph/api/organization-get, https://learn.microsoft.com/en-us/entra/identity-platform/howto-convert-app-to-be-multi-tenant
- Facts: `tid` "Represents the tenant that the user is signing in to." For personal accounts "the value is `9188040d-6c67-4c5b-b112-36a304b66dad`." `oid` is the immutable object id and differs per tenant for the same person. `sub` is pairwise per application. `preferred_username` and `upn` are mutable and must not be used for authorization. `GET /me` needs `User.Read`. `GET /organization` returns the tenant `id`, `displayName`, `verifiedDomains`, `tenantType`, and is "Not supported" for personal accounts. Multi-tenant apps read the tenant from `iss` and `tid`.

### 8.3 Slack identity

- URL: https://docs.slack.dev/reference/methods/auth.test, https://docs.slack.dev/reference/methods/oauth.v2.access, https://docs.slack.dev/reference/methods/team.info, https://docs.slack.dev/enterprise-grid/, https://docs.slack.dev/authentication/installing-with-oauth
- Facts: `auth.test` needs no scopes and returns `url`, `team`, `user`, `team_id` (`T...`), `user_id`, `bot_id` for bot tokens, and `enterprise_id` inside an Enterprise org. `oauth.v2.access` returns `access_token`, `token_type` (`bot` or `user`), `scope`, `bot_user_id`, `app_id`, `team.id`, `team.name`, `enterprise`, `is_enterprise_install`, `authed_user.id`, `authed_user.scope`, `authed_user.access_token`. `team.info` returns `team.id`, `team.name`, `team.domain`, `team.email_domain`, `team.enterprise_id`. In Enterprise Grid `team_id` means a workspace, org users share one identity across workspaces, and each workspace has its own app installation. "The `redirect_uri` must use HTTPS."
- Numbers: `expires_in` 43,200 s with token rotation.

### 8.4 GitHub identity

- URL: https://cli.github.com/manual/gh_auth_status, https://cli.github.com/manual/gh_auth_switch, https://cli.github.com/manual/gh_auth_login, https://raw.githubusercontent.com/cli/cli/trunk/pkg/cmd/auth/status/status.go, https://docs.github.com/en/rest/users/users, https://docs.github.com/en/rest/orgs/members, https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens
- Facts: `gh auth status` prints "Logged in to %s account %s (%s)", "- Active account: %s", "- Token scopes: %s" per host. `gh auth switch --hostname <host> --user <login>` changes the active account. `gh auth login` stores tokens in the system credential store with a plain-text `hosts.yml` fallback. `GET /user` returns `login`, `id`, `node_id`, `type`. `GET /user/orgs` needs `user` or `read:org` for classic tokens, and fine-grained tokens get an empty list. `GET /user/memberships/orgs` returns `state`, `role`, `organization.login`, `organization.id`. Fine-grained PATs are scoped to one resource owner.
- Numbers: `per_page` max 100. Fine-grained PAT default expiry 30 days, up to 50 per user.

### 8.5 OS and product precedents for realms

- URL: https://chromium.googlesource.com/chromium/src/+/main/docs/user_data_dir.md, https://support.google.com/chrome/answer/2364824, https://support.google.com/chrome/a/answer/11198768, https://developer.android.com/work/managed-profiles, https://developers.google.com/android/work/connected-apps/connected-apps, https://developer.apple.com/videos/play/wwdc2022/10121/, https://support.apple.com/guide/mac-help/mchl613dc43f/mac, https://developer.apple.com/videos/play/wwdc2021/10136, https://learn.microsoft.com/en-us/purview/sensitivity-labels, https://learn.microsoft.com/en-us/purview/default-sensitivity-labels-policies, https://learn.microsoft.com/en-us/purview/apply-sensitivity-label-automatically
- Facts: Chrome profiles "keep all your Chrome info separate, like bookmarks, history, passwords, and other settings" and let you "Keep your different accounts, like work and personal, separate." Each profile is a subdirectory under the user data directory, often `Default`. Enterprise profile separation: "No data or content is shared between profiles", with `ProfileSeparationSettings` Suggest, Enforce or Disable. Android work profile: "personal and work profiles have separate storage areas", most intents do not cross profiles, work apps carry a briefcase badge, personal apps do not show work contacts by default, and "Work data won't be accessible when the work profile is off." Apple Focus filters (iOS 16, macOS Ventura): apps adopt `SetFocusFilterIntent`, Mail filters accounts, Calendar filters calendars, Safari filters Tab Groups. Apple User Enrollment creates "a separate APFS volume with different cryptographic keys" for managed data, erased on unenrollment. Purview sensitivity labels are one stamp per item stored in clear text in metadata, with the suggested taxonomy Personal, Public, General, Confidential, Highly Confidential, a default label policy, inheritance from attachments to email, and client-side plus service-side auto-labeling that never replaces a manual label by default.
- Numbers: Purview effectiveness drops above five main labels. Android work profile from API 21.

### 8.6 Connector platform identity models

- URL: https://nango.dev/docs/reference/api/connect/sessions/create, https://nango.dev/docs/reference/api/connection/get, https://docs.merge.dev/hris/account-details/, https://docs.merge.dev/merge-unified/merge-link/relinking, https://docs.composio.dev/docs/auth-configuration/connected-accounts, https://developers.apideck.com/guides/understanding-consumers, https://docs.useparagon.com/apis/users.md
- Facts: Nango connect sessions carry `end_user.id`, `end_user.email`, `end_user.display_name`, `organization.id` (now tags `end_user_id`, `end_user_email`, `organization_id`). The connection object has `connection_id`, `provider_config_key`, `provider`, `end_user`, `connection_config`, `metadata`, `last_fetched_at` and `errors[]` with `type` `auth` ("Connection credentials are invalid") or `sync`. Merge `GET /account-details` returns `id`, `integration`, `category`, `end_user_origin_id`, `end_user_organization_name`, `end_user_email_address`, `status`, `account_type`, `completed_at`, and relinking keeps the id and token. Composio connected accounts are keyed by `user_id` and `auth_config_id` with statuses `ACTIVE`, `INACTIVE`, `REVOKED`, `EXPIRED` and `status_reason`. Apideck consumers have connection states `available`, `added`, `authorized`, `callable`, `invalid`. Paragon reports per-integration `credentialStatus` `VALID` or `INVALID`.
- Numbers: Nango tags max 10 keys.

### 8.7 Permission-aware indexing (identity agent)

- URL: https://docs.glean.com/security/security-principles, https://developers.glean.com/libraries/indexing-sdk/permissions, https://learn.microsoft.com/en-us/microsoftsearch/semantic-index-for-copilot
- Facts: Glean "mirrors the access controls of every connected source system" and "never grants broader access than the source system provides." Each indexed document carries `DocumentPermissionsDefinition` with `allowed_users`, `allowed_groups`, `allowed_group_intersections`, and connectors push an identity graph. "An ACL naming a group Glean has never heard of matches nobody." Microsoft 365 Copilot's semantic index is per tenant and per user, stored with the user's mailbox, and labels with encryption require the EXTRACT usage right.

### 8.8 Token storage

- URL: https://keith.github.io/xcode-man-pages/security.1.html, https://support.apple.com/guide/security/keychain-data-protection-secb0694df1a/web, https://docs.rs/keyring/latest/keyring/, https://docs.rs/keyring-core/latest/keyring_core/struct.Entry.html, https://docs.rs/security-framework/latest/security_framework/, https://docs.rs/secret-service/latest/secret_service/, https://specifications.freedesktop.org/secret-service/latest/, https://docs.rs/age/latest/age/, https://docs.rs/chacha20poly1305/latest/chacha20poly1305/, https://code.claude.com/docs/en/iam, https://www.silverfort.com/blog/skipping-the-lock-a-claude-code-cli-weakness-lets-any-macos-process-read-stored-credentials/
- Facts: `security add-generic-password` takes `-a`, `-s`, `-w`, `-T` (apps allowed to read) and `-A` (any app, "insecure, not recommended!"). "By default, the application which creates an item is trusted to access its data without warning." Keychain items are encrypted with AES-256-GCM and access is keyed to entitlements. `keyring` 4.2.0 (MIT or Apache-2.0) has pluggable stores (`apple-native-keyring-store`, `dbus-secret-service-keyring-store`, `linux-keyutils-keyring-store`) and `keyring-core` 1.0.0 exposes `Entry::new(service, user)`, `set_password`, `get_password`, `delete_credential`. `security-framework` 3.7.0. `secret-service` 5.2.0 (GNOME Keyring and KWallet implement the API). `age` 0.12.1 and `chacha20poly1305` 0.11.0 for an encrypted file alternative. Claude Code stores credentials in the macOS Keychain with a `~/.claude/.credentials.json` (0600) fallback. Third-party research names the item `Claude Code-credentials`, created without `-T`, so any process running `/usr/bin/security` can read it.

### 8.9 OAuth for native apps

- URL: https://datatracker.ietf.org/doc/html/rfc8252, https://datatracker.ietf.org/doc/html/rfc7636, https://datatracker.ietf.org/doc/html/rfc8628, https://developers.google.com/identity/protocols/oauth2/native-app, https://developers.google.com/identity/protocols/oauth2/limited-input-device, https://docs.notion.com/docs/authorization, https://linear.app/developers/oauth-2-0-authentication, https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps
- Facts: RFC 8252 loopback redirect is `http://127.0.0.1:{port}/{path}`, "The authorization server MUST allow any port to be specified", "the use of localhost is NOT RECOMMENDED", PKCE is required for public native clients. RFC 7636 `code_verifier` is 43 to 128 characters and S256 is mandatory when supported. Google Desktop app clients "cannot keep secrets", `client_secret` is optional on exchange, and "refresh tokens are always returned for installed applications". RFC 8628 device grant polls with `interval` default 5 s. GitHub device flow needs only a client id. Google device flow is limited to a few scopes. Slack requires an HTTPS `redirect_uri` with no localhost exception on the current page. Notion exchanges at `/v1/oauth/token` with Basic client auth. Linear supports PKCE with `client_secret` optional.
- Numbers: GitHub device code expires in 900 s. Linear access tokens 24 h.

## 9. Overseer account governance (local, read only)

- URL: `/Users/bilal/projects/overseer/docs/rfcs/account-governance.md` (proposed 2026-09-25).
- Facts: Overseer organizes logins as accounts, not harnesses. An account is a named provider login with its own 0700 credential folder, an identity fingerprint, a plan and a status. Providers are `anthropic`, `openai`, `devin`. A static compatibility map says which harness accepts which provider. A "linked desktop login" points at a harness's default folder, is labeled "follows <app>", is never logged out by Overseer, and the task picker warns it can change underneath. One account serves several harnesses through derived folders (`CODEX_HOME`, `CLAUDE_CONFIG_DIR`, `XDG_DATA_HOME`). Rules: account login only, no API keys, credentials never enter the database or events, only a one-way fingerprint, plan and timestamps are stored, removal touches only the account's folder, and a run records the account it used.
- Facts taken for mote: the registry row shape (provider, named account, fingerprint, status, last used), the "follows app" notion for a login mote does not own (`gh`, `claude`), and the rule that only a fingerprint is stored.
