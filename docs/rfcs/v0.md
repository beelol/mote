# mote v0: what to build, in order

Status: build contract, 2026-10-08. Every default here is decided. A driver follows this file
and the V0 list in the README. The long RFCs under `docs/rfcs/` and `docs/reuse/` are reference
only; nothing in them overrides this file.

## 0. Ground rules

- **Local only.** The config key `models.local_only` is `true` by default. While it is true, no lane may start Claude Code, Codex, or any subscription harness. The daemon refuses with a logged reason. The owner flips it later, in person.
- **Approved local models.** The driver may pull exactly these through Ollama and nothing else: `qwen3:4b` (2.5 GB, talk), `qwen3:0.6b` (0.6 GB, router), `qwen3-coder:30b` (19 GB, think, with a Modelfile setting `num_ctx 65536`). Total 22 GB. Any other pull waits for the owner.
- **Memory gate.** A model loads only when free memory is at least 1.25 times its file size. The Mac has 128 GB. The gate reads real free memory, never a constant.
- **Context size.** Every Ollama call sets `num_ctx` explicitly. Minimum 32768 for any model that uses tools.
- **Verdicts.** Every model decision is a JSON object parsed fail-closed. Unknown fields, missing fields, trailing text or prose mean failure. No regex over natural language.
- **Tests.** `cargo test --workspace` runs with no network against the test kit. Live checks run only with `MOTE_LIVE=1` and are recorded in `docs/verification/<ID>.md` with command, output and date.
- **Quality bar.** `cargo clippy --workspace -- -D warnings` clean. Rust 2021. Conventional Commits. No AI attribution trailers.
- **Secrets.** Redaction runs on every event before storage. No secret ever enters a model call.
- **Not in v0.** Voice, the attention detector, the Pi, the relay, Slack and GitHub connectors, browser use, the Overseer work lane, and every subscription harness. They live in `docs/backlog.md` and start when the owner says so.

One Cargo workspace. Binaries: `moted` (mote-cloud) and `mote-client`. Crates under `crates/`:

Data directory: `~/Library/Application Support/mote` on macOS, mode 0700. One SQLite file `mote.db` in WAL mode holds every table below.

## 2. Event log

Table `events(seq INTEGER PRIMARY KEY AUTOINCREMENT, ts, scope_id, kind, payload TEXT)`. `payload` is JSON, already redacted. A client subscribes with a cursor and receives every event with `seq > cursor` in order, then live events, never a duplicate. Retention: 5,000 events per scope; older rows are replaced by one `retention` marker row. A subscriber that lags more than 1,000 events gets a `resync` event and replays from the log.

## 3. IPC

Unix socket at `<data dir>/moted.sock`, mode 0600. Newline-delimited JSON. Requests: `{"id","method","params"}`. Replies: `{"id","result"}` or `{"id","error":{"code","message"}}`. Codes: `parse_error`, `invalid_request`, `invalid_params`, `internal`. Max request 1 MiB. Method `events.subscribe {scope_id, cursor}` streams `{"event":{...}}` lines until the connection closes. A peer with another uid is refused. A second `moted` on the same socket exits non-zero naming the path.

## 4. Config

`<data dir>/config.toml`, created with defaults on first start:

```toml
[models]
local_only = true
talk = "qwen3:4b"
router = "qwen3:0.6b"
think = "qwen3-coder:30b-64k"

[budgets]            # milliseconds, p50
talk_first_token = 300
router = 150
think_first_token = 3000

[packs]              # tokens
talk = 600
think = 8000
```

Every key is changeable at runtime through `config.set {key, value}` over IPC. The daemon validates the change (a model over the memory gate is refused with the reason), writes a `config.changed` event with old and new values, and applies it on the next turn. `config.revert {seq}` restores the value from that event.

## 5. Local model client

`mote-localmodel` talks to Ollama at `http://127.0.0.1:11434`. It streams `/api/chat`, sets `keep_alive` to 30 minutes and `num_ctx` from config, and supports `format` with a JSON schema for structured output. `ensure(model)` checks the model exists, checks the memory gate, loads it, and returns the measured load time. The test kit's scripted server speaks the same endpoints.

## 6. Talk lane

Input: a user message in a thread. Output: streamed tokens as `talk.delta` events and one `talk.done` event with the ledger row id. The talk lane never calls tools. Its pack is: charter, profile, the last 8 memories by retrieval, the working set, the turn, within 600 tokens. First token p50 under 300 ms on the Mac with the model warm. Fallback when the model cannot load: a `talk.unavailable` event with the reason, no silent substitute.

## 7. Router

Runs in parallel with the talk lane on every turn. Model `qwen3:0.6b` with a JSON schema `{"route": "talk" | "think", "reason": string}` and a fixed few-shot prompt stored in the repo. Parsed fail-closed: anything invalid is `think`. The budget is 150 ms p50. `work` is not a v0 route; the work lane is in the backlog. When the verdict is `think`, the talk lane finishes its current sentence and emits `talk.handoff`.

Accuracy gate: the test kit carries 30 labelled turns per route. The router must reach 0.85 macro-F1 on them. If it does not, the driver writes the measured number in the evidence file and keeps going; improving the router is a backlog item.

## 8. Think lane, local

Harness: OpenCode, launched by `mote-harness` with its model set to `qwen3-coder:30b-64k` through Ollama. The harness stream is parsed into normalized events (`think.text`, `think.tool_call`, `think.tool_result`, `think.done`). Tools reach the model through one MCP server, `moted mcp`, over stdio: `memory_search`, `memory_write`, `file_read`, `file_list`. No other tools in v0. A think turn ends with a ledger row. First token p50 under 3 s. When `models.local_only` is true and the config names Claude or Codex, the daemon refuses at startup with a logged reason.

## 9. Context store, packs, ledger

Tables: `profile(key, value)`, `working_set(thread_id, seq, text)`, `packs(id, lane, parts TEXT, token_estimate, created_at)`, `ledger(id, ts, lane, model, pack_id, prompt_tokens, completion_tokens, latency_ms, cost_usd, status)`. A pack is an ordered list of parts, each `{kind, source_ref, hash, tokens}`. Part order is fixed: charter, profile, memory, working set, turn. Tokens are estimated with `tiktoken-rs` `o200k_base`. Every model call writes exactly one ledger row and one pack row. Packs are kept 30 days.

## 10. Memory graph

Tables: `mem_node(id, kind, realm, text, embedding BLOB, source_seq, created_at, valid_from, valid_to, superseded_by)`, `mem_edge(src, dst, kind, realm, source_seq, valid_from, valid_to)`, `mem_fts` (FTS5 over `text`), `mem_vec` (sqlite-vec, int8[256]). Kinds: `entity`, `event`, `procedure`, `summary`. Embeddings come from `model2vec-rs` with `potion-base-8M` (30 MB, pinned by hash). A write is one transaction and zero model calls. Retrieval for a query: top 20 by FTS5, top 20 by vector, their 2-hop neighbours bounded to 200 edges per node, fused by reciprocal rank with k=60, recency decay with a 30-day half-life, deduplicated, cut to the lane's budget. Forgetting sets `superseded_by`; nothing is deleted. `realm` defaults to `personal` in v0.

## 11. Charter

`<data dir>/house.md` and `<data dir>/characters/<name>.md`. Each file starts with a TOML front matter block the daemon enforces:

```toml
name = "mote"
tools = ["memory_search", "memory_write", "file_read", "file_list"]
realms = ["personal"]
```

The prose after the front matter is the first pack part of every call. The files are watched; a change is a `charter.changed` event. The model has no tool that writes them.

## 12. Surface tree

Compact JSON, `type` first, `children` last. Node types: `text`, `stack`, `row`, `list`, `table`, `field`, `toggle`, `select`, `action`, `progress`, `chat`. Limits: depth 12, 2,000 nodes, 256 KB. Events from the renderer: `{"event": name, "args": {...}}`. The validator rejects unknown types, unknown keys and limit breaches; a rejected tree becomes a `text` node with the diagnostic. A JSON Schema is generated from the Rust types and committed at `schemas/tree.v0.json`. Ten fixtures under `crates/mote-ui/fixtures/` pair a tree with a PNG rendered by the test renderer.

## 13. mote-client

A native window built with `eframe` (egui). It connects to the socket, subscribes from its saved cursor, and shows threads as chat. Each message shows one of `sending`, `sent`, `delivered`, `read` and a typing indicator while `talk.delta` events arrive. A reply that carries a surface renders it inline through `mote-ui`. Button presses and form submits go back as `ui.event`. Closing and reopening the window resumes from the cursor with nothing shown twice. Theme follows the system, light and dark.

## 14. Pipeline view

A second screen in mote-client. One row per stage: talk, router, think, memory, ledger. Clicking a stage shows four tabs: Now (live events), Config (every key from section 4 as a control), Numbers (p50 and p95 latency, tokens, cost over the last hour against the budget), Requests (every outbound call with redacted payload and timing). A control change calls `config.set`. Opening the view adds under 5 ms at p50 to the talk lane.

## 15. Watchers and approvals

A `schedules(id, cron, prompt, enabled)` table and a tick loop fire a prompt into a thread as if the owner typed it. An `approvals(id, thread_id, kind, payload, status, expires_at)` table holds every outward action; in v0 the only kind is `file_write` outside the data directory. The client shows an approval as a card with Approve and Deny. Nothing with status `pending` executes. Approvals expire after 24 hours.

## 16. Service

`moted install` writes a launchd agent `com.mote.moted` with KeepAlive and log paths under the data directory, and loads it. `moted uninstall` removes it. `moted status` prints socket, uptime, loaded models and the last event seq.

## 17. Bench

`moted bench talk`, `moted bench router`, `moted bench memory` print p50 and p95 over 20 runs against the live local models and write a JSON line to `<data dir>/bench.jsonl`. Their output is the evidence for every latency criterion.
